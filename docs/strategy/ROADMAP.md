# מצב נוכחי מול התוכנית האסטרטגית

`docs/strategy/plan.md` הוא מסמך האסטרטגיה הקבוע (קריאה בלבד, לא
נערך כאן - ראו הכותרת שלו). המסמך הזה הוא רק "היכן אנחנו עומדים
עכשיו" ביחס אליו - מתעדכן בכל סבב עבודה.

## שלב נוכחי: שלב 0 (פריסה) - כמעט הושלם

- ✅ Vercel - **חי**: https://legislator-tau.vercel.app, מחובר
  ל-GitHub, דחיפה ל-master מעדכנת אוטומטית. אומת מקצה לקצה (עמוד,
  static, API, ייצוא docx). ראו `decisions.md` לפרטי התצורה.
- ✅ סביבת production + local (שתיהן עובדות). Preview לכל ענף - לא
  נבדק עדיין בפועל (אמור לעבוד אוטומטית דרך חיבור ה-GitHub, לא
  אומת ישירות).
- ❌ **לא בתוכנית יותר, במפורש:** הגנת סיסמה - ברק החליט שלא, בכל
  שלב, עד הודעה אחרת. האתר ציבורי במכוון.
- ⏸ דומיין מותאם אישית - לא נרכש (עלות כסף, דורש אישור מפורש בכל
  פעם - טרם התבקש).
- ⏸ Supabase - עדיין לא הוקם פרויקט ייעודי ל-Legislator (שני
  הפרויקטים הקיימים בחשבון לא קשורים - ראו למטה).

**"הסתיים כאשר" של plan.md §0** ("דחיפה ל-main מעדכנת את האתר בלי
מגע יד, ואתה פותח אותו מכל מכשיר") - **מתקיים בפועל**, מלבד דומיין/
סיסמה שהוחלט במפורש להשאיר בצד.

## מה כבר קיים (מחוץ לסדר של plan.md, מלפני שהוא נכתב)

- לשונית "הצעות חוק": מנוע + API + ממשק עובדים על שני חוקי fixture,
  בלי דאטהבייס (state בלקוח בלבד). עיצוב לפי docs/design/ - הושלם.
  זה **לא** תואם עדיין את plan.md (שמצפה לקורפוס מלא מ-Supabase לפני
  שהכלי "נסגר" בשלב 3) - נשאר על fixtures עד שלב 1 יושלם.
- `docs/design/` (מוקאפ עיצובי + README) - תואם לשלב 0/כל השלבים,
  לא ספציפי לשלב אחד.

## תשתית קיימת רלוונטית לשלב 1

- שני פרויקטי Supabase בחשבון ("121", "ניהול מפעלים") - **אף אחד
  מהם לא שייך ל-Legislator**. שלב 1.1 דורש פרויקט Supabase חדש
  ייעודי (Postgres + pgvector).
